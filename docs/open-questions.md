## 3. evidence

### 跨多条 L0

先澄清：L0 是**一轮一条**，里面已经包含双方：

```text
L0#1
主人：我牙疼
我：去看看
```

所以同一轮里的“主人：……”和“我：……”本来就在同一条 L0 里，不需要拆。

真正跨 L0 是跨轮：

```text
L0#1
主人：我牙疼
我：去看看

L0#2
主人：看完了，医生说没事
我：那就好
```

如果 evidence 拼了两轮：

```text
主人：我牙疼
……
主人：看完了，医生说没事
```

它不属于任何单条 L0。

逐条匹配时：

```text
evidence 对 L0#1 → 只覆盖前半
evidence 对 L0#2 → 只覆盖后半
→ 低于 0.85
→ unverified
```

这才是“跨多条 L0”。

需要支持：

```text
把相邻 2–3 条 L0 拼起来再匹配
匹配到哪几条，就写哪几条 id
```

注意：

```text
不需要拆 L0 存储
L0 一轮一条是对的
要拼的是匹配窗口，不是存储
```

模型可能给多句 evidence：

```json
"evidence": [
  "主人：我牙疼",
  "主人：看完了，医生说没事"
]
```

那就分别匹配，不需要拼成一句。

问题只出在模型把两轮拼成了一句。

或者提示模型：

```text
一次 evidence 只抄一条消息
不要跨消息拼接
```

两种可以一起做。

### 多段 evidence

这不是匹配问题，是来源分段问题。
