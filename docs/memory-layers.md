# 记忆分层

状态：方案，未实现。

## 1. 结论

不新增 L5。

现有五层够用，但职责要重排：

```text
L0  原话
L1  事实
L2  核心记忆
L3  普通经历
L4  规矩候选
```

人格独立在外面，作为稳定配置和长期叙事的唯一来源。

```text
人格：我是谁、我怎么想、我们是什么关系
L2  ：少数忘不掉的具体事件
L4  ：还没被人格确认的规矩候选
```

B 站和自主活动不进 memory，进 activity。

## 2. 现在的问题

### 2.1 L2 被用户画像占了

当前 L2 是自动用户画像。

它和人格里的：

```text
用户画像
核心设定
```

大量重合。

结果是：

```text
同一件事既在 L2
又在 persona.user_profile
```

每轮还被 `profile()` 一起注入。

### 2.2 L3 混了两种东西

L3 现在同时装：

```text
真实经历
B 站浏览
自主活动
```

但这两类东西的生命周期和意义完全不同。

```text
一起经历的事：值得记很久
今天刷了什么：只是当天行为
```

### 2.3 L4 和人格重复

人格里已经有：

```text
核心设定：关系、边界、约定
重要约定
用户画像：boundaries
```

L4 又在 memory 里装：

```text
关系 / 规矩
```

如果两边都注入，就是两个事实源。

### 2.4 没有“忘不掉的事件”

L3 是 90 天半衰期的普通事件。

L4 只收规矩。

所以第一次、承诺、关系转折、真正被击中的时刻，没有稳定位置。

## 3. 新分层

### L0 原话

不变。

```text
原始对话
```

### L1 事实

```text
他教初中数学
他养了只猫叫豆豆
他最近在准备转正
```

一句话一条。

稳定事实可以长寿命，不再 30 天就淡掉。

### L2 核心记忆

从 L3 提升上来的少数事件：

```text
第一次见面
他真正把我当“人”看的那晚
一次很重的承诺
关系转折
后来反复想起的事
```

特点：

```text
少
不衰减
不常驻 prompt
按需召回
```

不是每轮抽取器直接写，而是由复盘/人格模块从 L3 提升。

### L3 普通经历

```text
今天聊了什么
一起看了什么
发生了什么小事件
```

普通事件线，保留衰减。

B 站、自主活动不默认进这里。

### L4 规矩候选

L4 不再做“关系叙事”，只做：

```text
他明确说过的要求
称呼
边界
禁止事项
相处规则
```

但 L4 不是最终事实源。

L4 是**候选层**：

```text
对话里出现规矩
→ 写 L4 候选
→ 人格复盘确认
→ 写入 persona important / 核心设定
→ L4 标记 applied
```

## 4. 人格负责什么

人格仍然是：

```text
我是谁
我的性格
我怎么说话
我眼中的主人
我们是什么关系
```

具体分层见 [人格分层](persona-layers.md)。

人格是稳定配置和长期叙事的唯一来源。

```text
人格：稳定、确认过、可编辑
L2  ：具体事件，不是人格结论
L4  ：待确认的规矩，不是最终规则
```

## 5. L4 和人格到底重不重复

结论：

```text
如果 L4 是最终规则源：重复
如果 L4 是候选层：不重复
```

### 重复的用法

```text
L4 存“以后叫我老王”
人格 important 也存“以后叫我老王”
两边都每轮注入
```

这是两个事实源。

模型会看到两遍，修改时也可能只改一边。

### 不重复的用法

```text
L4：2026-11-06 他说以后叫他老王（pending）
人格 important：以后叫他老王（confirmed）
```

L4 是证据和候选，人格是生效规则。

生效后：

```text
L4 status = applied
不再注入
```

## 6. 写入流程

```text
对话
  ├─ L1 事实
  ├─ L3 普通经历
  │    └─ 复盘提升 → L2 核心记忆
  └─ L4 规矩候选
       └─ 人格复盘确认 → persona important / 核心设定
```

B 站：

```text
B 站 / 自主活动
  └─ activity
```

只有引发真实对话才：

```text
activity + chat → L3
```

## 7. L2 提升标准

不是“重要一点的 L3”。

候选条件：

```text
第一次
承诺
关系转折
强烈情绪
后来反复被提起
对之后的行为有持续影响
```

数量控制：

```text
初期最多 20 条
稳定后最多 50 条
```

提升由复盘完成，不由每轮抽取器直接写。

L2 记录应该带：

```text
为什么留下
来源 L3 / L0
发生时间
```

## 8. L4 候选状态

建议字段：

```text
status: pending / applied / rejected
target: important / 核心-约定 / 核心-边界
evidence: 原话或 L0
confirmed_at
```

只有：

```text
status = pending
```

的候选需要短时间注入提醒。

生效后：

```text
status = applied
不再单独注入
```

避免和人格重复。

## 9. 检索与注入

### 默认对话

```text
人格
+ L1 相关事实
+ L3 相关经历
+ L2 少量核心记忆（高门槛）
```

### 规矩

```text
人格 important / 核心设定
+ 尚未确认的 L4 pending
```

已 applied 的 L4 不再注入。

### B 站

```text
activity
```

不参与 memory 检索。

### 日记

```text
当天情绪事件
+ 对应 L0
+ L3 旧记忆
+ activity 补充
```

## 10. 迁移

### L2

现在 L2 是用户画像，不能直接当核心记忆。

建议：

```text
备份现有 L2
把仍然有效的稳定事实迁到 persona.user_profile
清空 L2
以后 L2 只由复盘提升写入
```

### L4

现有 L4 分两类：

```text
明确规矩 → 迁到 persona important / 核心-约定 / 核心-边界
关系叙事 → 迁到 L2 核心记忆或人格
```

迁移后 L4 只保留 pending 候选。

### L3

现有 L3 里的 B 站/自主活动：

```text
历史数据可以保留
新数据不再写 L3
```

需要时按 tags 或来源单独标记。
