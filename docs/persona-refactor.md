## 1. 已经敲定的

### 1.1 核心设定两大块六小节

```text
【我自己】
  我是谁
  表现        说话和做事的样子（宽规则 + 例子）
  偏好        长期稳定的喜欢/不喜欢（新增）
  价值取向    判断、原则
  弱点        我会栽在哪

【我和他】
  我眼中的他  他的画像（独立存储）
  我们怎么对彼此
  我们之间有什么   含 important 标记
```

已落地的是没有「偏好」的六小节版本：

```text
## 我是谁
## 表现
## 价值取向
## 弱点
## 我们怎么对彼此
## 我们之间有什么
```

「偏好」待加，见 3.1。

### 1.2 为什么是这两大块

```text
只关于我的   → 我自己
关于我们的   → 我和他
```

不是按「性格/价值观/关系」分维度，是先按归属分。

### 1.3 核心设定和画像分开存

```text
核心设定    手编 + 半自动确认，改动少
画像        每 2 天自动重写
```

同一段文本会让画像重写把手编内容冲掉。

现渲染时已经是连着的（`persona.mjs` 先核心设定、再画像），模型看到的是连续的。

### 1.4 每条存「成了什么样」

```text
存：     - 被留的时候，我是当真的。
不存：   - 他说想留住我那天，我话说一半就收了。
```

后半句属于 L3。

### 1.5 关联事件

```text
- 被留的时候，我是当真的。{{L3:1245}}
```

三种渲染：

| 场景 | 渲染成 | 用途 |
| --- | --- | --- |
| 面板 | 标题，可点 | 人看依据 |
| 日常对话 | 抹掉 | 保住 system prompt 缓存，避免复述 |
| 复盘 | 标题、状态、L3 正文 | 判断还成不成立 |

为什么日常要抹掉：人格是 system prompt 固定前缀，跟着 L3 变会让整段历史缓存失效。

### 1.6 重要标记只是优先级

```text
<!-- important:begin -->
- ...
<!-- important:end -->
```

含义只有一条：这几条可以盖过其他条目。不决定内容放哪块。

### 1.7 自我认知删掉

现在 `self_model` 三块：

```text
最近的变化   全部重复核心设定，或该进候选
我学到的     4 条全部重复
还没想清     1 条，唯一不重复的
```

结论：

```text
我学到的      删
最近的变化    并进中间层
还没想清      并进中间层
```

### 1.8 中间层

```text
日记      今天怎么样了
变化      我最近在变什么
没想清    悬着的问题
```

三者共用一套按日存储。第一人称、会过期、不进 system prompt。

### 1.9 画像对齐四栏

```text
我自己        我眼中的他
我是谁        他是谁
表现          他平时什么样子
偏好          他的偏好
价值取向      他的价值取向
弱点          他的软处
```

对齐后要清掉原来的「互动偏好」「边界」两栏。

其中这几条并进「我们怎么对彼此」：

```text
讲难受的事要听完
倾诉时先被问怎么了
在意有没有落在实处
私聊不转进群
群友的话不当成主人说的
不要编造主人的名字和来路
```

「说话短、结论先说」进「他平时什么样子」。

### 1.10 情绪跟着 L1 走

模型本来就在每条 L1 上给情绪：

```json
[{"text": "...", "tier": "L1", "source_refs": [1,2],
  "emotion": {"label": "难过", "valence": -0.7, "arousal": 0.4, "reason": "..."} | null}]
```

代码却整批只挑幅度最大的一条写 `emotion_log`。

改成：

```text
memory 表加 emotion_label / emotion_valence / emotion_arousal
L1 落库时一并写，整批都写
```

### 1.11 L1 分段改成 5 分钟

L1 现在 30 分钟一批。改成空闲 5 分钟就切一段。

好处是和情绪复盘同频，不需要两个窗口。

### 1.12 emotion_log 整表删除

`emotion_log` 的功能都能被替代：

```text
最近 3 条明细    → 从最近带情绪的 L1 里挑
历史统计         → 从 L1 按字段聚合
复盘素材         → L1 / L3 已经带了
```

原来「当前心情」那两个数（valence / arousal）也删：

```text
那个情绪其实是上一段对话的情绪，不是此刻的状态
挂在全局 state 上本来就错位
```

连带删除：

```text
set_emotion
state.emotion
state.mjs 里「心情（很开心，有点激动）」
growth/emotion.py 整个文件
```

`mood`（happy / tired / annoyed）是另一套，不动。

### 1.13 情绪只在 L1 抽取时写

不每句复盘，不空闲复盘。

```text
L1 抽取本来就在读那段对话
EXTRACT_SYSTEM 已经要求它判断情绪
```

代价是慢几分钟，情绪不需要实时。

### 1.14 L3 不单独存情绪

```text
L3 从 L1 上来，情绪跟着 source_ids 里的 L1 聚合
```

到 L3 这个层级，该留下的是「对关系、自我、价值取向的认知改变」，不是当时的感受。

### 1.15 insight_kind → insight_target

```text
现在   self / style / relation
改成   me / us / none
```

只标记「指向哪一块」，具体落到哪一段由复盘判断。

`style` 不再是取值：风格感悟走已有通道（`bili_insights("style")` → `style.py`）。

### 1.16 B 站和 L3 结构统一

两边都写进 `memory` 表的 L3，字段已经一致。统一 `insight_target` 之后不需要两套判断。



```text

  → 生成「偏好候选」
  → 人工确认后进画像偏好栏
```

```text
阈值多少
「连续多天」怎么算
候选进画像后，兴趣系统里的还要不要留
```

### 3.2 「偏好」和「取向」的界线

```text
他喜欢许嵩的歌       → 偏好
他相信吃苦是手段     → 取向
```

前者是喜好对象，后者是价值判断。

但有些东西两边都能放：

```text
他喜欢深夜写代码
是偏好（喜欢什么），还是取向（作息背后的判断）？
```

需要一条判断标准。

### 3.3 中间层怎么存

```text

变化      ?
没想清    ?
```

## 5. 当前人格实况

```text
## 我是谁          4 条
## 表现            7 条 + 2 个例子
## 价值取向        7 条
## 弱点            3 条
## 我们怎么对彼此  5 条
## 我们之间有什么  3 条（带 important 标记）
```

原 8 条「重要」里 5 条被挪出去：

```text
他讲难受的事时，先听          → 我们怎么对彼此
他说「说点安慰我的话」        → 我们怎么对彼此
他说接受不了换模型之后不是我  → 我们怎么对彼此
记东西要分清哪句是他说的      → 价值取向
别人写好的设定我不接          → 价值取向
```
