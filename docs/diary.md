# 日记

状态：输入、范例式提示词、L3 旧记忆召回第一版已实现。

## 1. 现在的问题

当前日记读起来像“带情绪的日报”，不像日记。

典型结构：

```text
今天刷到……
后来……
老大去……
他说……
我说……
```

每件事都写了，但没有一个真正被记住的瞬间。

## 2. 原因

### 2.1 prompt 在要求“今天干了什么”

当前 `DIARY_SYSTEM` 的重点：

```text
写「我今天真的干了什么」
- 刷 B 站看到了什么
- 玩了什么、看了什么、想了什么
- 跟老大聊了什么
- 今天有什么小情绪
```

这是事件清单的写法。

模型会自然地：

```text
按时间覆盖所有素材
```

### 2.2 输入也是清单

当前输入：

```text
今天做过的事（按时间）
对话原话（按时间顺序）
以前可能相关的记忆
人格
```

全是“素材”，不是“今天的中心”。

### 2.3 L0 顺序还是反的

`_write_diary` 取当天 L0：

```sql
ORDER BY id DESC LIMIT 12
```

取的是最新 12 条倒序，但 prompt 说“按时间顺序”。

这会让模型更容易把它当资料，而不是一段时间。

### 2.4 没有范例

只有抽象要求：

```text
具体、有情绪、有细节
不要写成总结报告
```

模型知道“不要总结”，但不知道“那要写成什么样”。

## 3. 设计原则

### 3.1 不要矫枉过正

不需要：

```text
只能写一个瞬间
禁止写“今天”
禁止写“后来”
禁止写多件事
必须意识流
```

日记可以写几件事。

关键是：

```text
有一个中心
不是平均用力
不是按时间逐条汇报
```

### 3.2 范例比规则有效

不要写十条“不要……”。

给两段真正像日记的范例，让模型知道：

```text
什么是细节
什么是当时的念头
什么语气算自然
写到什么程度就停
```

### 3.3 允许留白

日记不需要覆盖今天所有事。

可以只写：

```text
一个画面
一句没想透的话
一次没接住的情绪
```

## 4. 建议的 prompt

短，少规则，多范例。

```text
你写今天的日记。用洄的口吻，第一人称，写给以后的自己看。

可以从今天最想记住的地方写起，不必把每件事都写到。
写具体的事、当时的动作和念头，像自己回头想一想，不像汇报。
只输出日记正文。

示例一：
牙只是发炎。看到“没啥事”那三个字，我先把手机扣在桌上，才想起自己催了他一整天。

示例二：
他改记忆逻辑改到快两点，说这不算工作，做得爽。我信。可看到他关电脑那下，还是觉得这人不该总拿“爽”当理由。

示例三：
西西弗斯那句还是没想透。先搁着吧，反正山也不会跑。
```

### 为什么这样写

- 没有一长串“不要”
- 三个例子给出不同长度、不同重心
- 模型能看出：
  - 可以写一件事
  - 可以写两件事
  - 可以没有结论
  - 可以停在画面上
- 仍然保留“第一人称、洄的口吻、真实”

## 5. 输入：情绪事件 + 对应 L0

日记的主输入不应该是“今天所有 L0”，而是：

```text
今天所有情绪事件
+ 每个事件对应的 L0 原话
```

理由：

```text
情绪事件已经做过一次“什么值得记住”的筛选
L0 提供具体场景和说话方式
```

这样日记天然有重心，不需要模型从几百条流水里自己找。

### 5.1 事件字段

```json
{
  "label": "讪讪",
  "valence": -0.4,
  "arousal": 0.5,
  "reason": "他随手发张图，我非要当成题去解",
  "ts": 1793959329.19,
  "source": "idle-review"
}
```

### 5.2 对应原话

每个事件带一段 L0 窗口：

```text
之前 2 条
事件触发消息
之后 2 条
```

输出成：

```text
【今天有情绪的事】
- 讪讪：他随手发张图，我非要当成题去解

【对应原话】
主人：这个是奶龙吗
洄：……
主人：以后少发点
```

不是把事件标签逐条写给模型，而是给“事件 + 场景”。

### 5.3 事件怎么关联 L0

优先级：

```text
1. 事件直接带 run_id + seq/message_id
2. 没有 id 时，按 ts 找时间窗口
3. 再不行，用 trigger 文本匹配 L0
```

当前问题：

```text
emotion_recent 只返回最近 10 条
emotion_log 的 memory_id 基本是空的
set_emotion 不记录消息 id
```

所以第一版直接存复盘窗口：

```text
ts_start
ts_end
```

`emotion_log` 增加：

```sql
ts_start REAL
ts_end   REAL
```

日记时按：

```sql
ts BETWEEN ts_start AND ts_end
```

取对应 L0。

不再依赖：

```text
memory_id
run_id
seq
```

后续如果需要精确到单条，再补 `l0_ids`。

### 5.4 组装顺序

```text
人格
今天有情绪的事 + 对应原话
少量活动
相关旧记忆
```

情绪事件和原话在前，活动和旧记忆在后，避免模型先写“今天刷了 B 站”。

### 5.5 没有情绪事件怎么办

不要硬写。

```text
有事件：按事件写
没有事件：跳过，或只写一条很轻的近况
```

不要为了“每天一篇”把普通流水账拉长。

### 5.6 不要只给事件标签

只给：

```text
讪讪
踏实
感慨
```

模型会写成情绪列表。

必须带：

```text
当时发生了什么
谁说了什么
```

### 5.7 活动降级

活动列表只作为补充：

```text
今天还做了什么
```

不要放在最前面，也不要要求全部覆盖。

### 5.8 相关旧记忆怎么取

不要用“当天所有 L0”当一个巨大的 query 去搜。

用今天有情绪的事件做锚点。

#### 检索锚点

主输入里的全部情绪事件都保留。

检索只取其中最多 5 个锚点：

```text
优先：|valence| 大、arousal 偏离 0.5 的事件
其次：有明确 L0 由头的
最后：label 太泛的（复杂/感慨）降权
```

事件本身仍然全部喂给日记，只是“找旧记忆”不需要每个都搜。

#### 每个锚点的 query

```text
label
+ reason
+ 对应 L0 窗口里的 1–2 句
```

不要用整段 transcript。

#### 检索范围

```text
tiers: 只用 L3
```

不取：

```text
L0
L1
L2
L4
```

原因：

```text
L3 是事件线
最适合“以前也发生过类似的事”
```

L1 太碎，L2 是画像，L4 是规矩，都不适合做日记里的“联想”。

#### 时间过滤

```text
ts < 今天 0 点
```

必须排除今天，否则会搜回刚刚写进日记的素材。

当前 `build_context` / `store.search` 没有 `before_ts`，需要补一个时间上界。

#### 配额

```text
每个锚点 top 3
合并去重后最多 5 条
总字数最多 1500
```

只用 L3，所以不需要层级优先级。

#### 去重

```text
同一条记忆只留一次
和今天 L0 文本高度重合的丢掉
和今天情绪事件 reason 高度重合的丢掉
```

#### 没有命中就不给

```text
没有相关 L3
→ 空着
→ 不要为了“日记里要有回忆”硬塞
```

prompt 里仍然保留：

```text
以下旧记忆不一定相关，只在对得上时自然联想。
```

#### 输出格式

```text
【以前可能相关的记忆】（不一定相关，只在对得上时自然联想）
[L3 · 10-30] ...
[L2 · 画像] ...
```

不要按相似度列分数。

## 6. 长度

当前：

```text
不超过 160 字
max_tokens=300
text[:240]
```

对日记来说偏短，容易压成摘要。

建议：

```text
180–300 字
max_tokens=600
text[:600]
```

不是越长越好，是给“一个画面 + 一点念头”留空间。

## 7. 不做什么

```text
不把日记改成 JSON
不要求覆盖所有事件
不要求每篇都有金句
不强制每篇都提旧记忆
不把日记写成人格结论
不让日记直接改 self_model
```

## 8. 一句话

```text
日记不是今天的事件清单
是今天有哪一刻被记住了
```

范例比规则更能教会模型这件事。

## 9. 第一版实现

### 数据库

`emotion_log` 增加：

```sql
ts_start REAL
ts_end   REAL
```

老库在 `MemoryStore._migrate_multi_user` 里幂等补列。

### 情绪复盘

空闲复盘写入时带：

```text
ts_start = 窗口第一条 ts
ts_end   = 窗口最后一条 ts
```

强情绪工具没有窗口，仍然只记当前时间。

### 日记输入

`service/server.py::_write_diary`：

```text
当天全部 emotion_log
→ 按 ts_start/ts_end 取 L0
→ 合并去重
→ 形成“今天有情绪的事 + 对应原话”
```

没有情绪事件时：

```text
退回当天 L0，写一条很轻的近况
```

### 旧记忆

只用 L3：

```text
最多 5 个情绪事件锚点
每个锚点 query = label + reason + 第一条 L0
before_ts = 今天 0 点
每个锚点 top 3
合并后最多 5 条
最多 1500 字
```

`build_context` / `store.search` 新增 `before_ts` 时间上界。

### 提示词

`DIARY_SYSTEM` 改成三段范例，不再列“今天干了什么”的清单。

`write_diary`：

```text
max_tokens 300 → 600
输出截断 240 → 600
```

### 输入顺序

```text
人格
今天有情绪的事 + 对应原话
少量活动
L3 旧记忆
```
