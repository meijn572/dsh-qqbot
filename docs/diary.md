# 日记

状态：方案，未实现。

## 1. 现在的问题

当前日记读起来像“带情绪的日报”，不像日记。

典型结构：

```text
今天刷到……
后来……
老大去……
他说……
我说……
```

每件事都写了，但没有一个真正被记住的瞬间。

## 2. 原因

### 2.1 prompt 在要求“今天干了什么”

当前 `DIARY_SYSTEM` 的重点：

```text
写「我今天真的干了什么」
- 刷 B 站看到了什么
- 玩了什么、看了什么、想了什么
- 跟老大聊了什么
- 今天有什么小情绪
```

这是事件清单的写法。

模型会自然地：

```text
按时间覆盖所有素材
```

### 2.2 输入也是清单

当前输入：

```text
今天做过的事（按时间）
对话原话（按时间顺序）
以前可能相关的记忆
人格
```

全是“素材”，不是“今天的中心”。

### 2.3 L0 顺序还是反的

`_write_diary` 取当天 L0：

```sql
ORDER BY id DESC LIMIT 12
```

取的是最新 12 条倒序，但 prompt 说“按时间顺序”。

这会让模型更容易把它当资料，而不是一段时间。

### 2.4 没有范例

只有抽象要求：

```text
具体、有情绪、有细节
不要写成总结报告
```

模型知道“不要总结”，但不知道“那要写成什么样”。

## 3. 设计原则

### 3.1 不要矫枉过正

不需要：

```text
只能写一个瞬间
禁止写“今天”
禁止写“后来”
禁止写多件事
必须意识流
```

日记可以写几件事。

关键是：

```text
有一个中心
不是平均用力
不是按时间逐条汇报
```

### 3.2 范例比规则有效

不要写十条“不要……”。

给两段真正像日记的范例，让模型知道：

```text
什么是细节
什么是当时的念头
什么语气算自然
写到什么程度就停
```

### 3.3 允许留白

日记不需要覆盖今天所有事。

可以只写：

```text
一个画面
一句没想透的话
一次没接住的情绪
```

## 4. 建议的 prompt

短，少规则，多范例。

```text
你写今天的日记。用洄的口吻，第一人称，写给以后的自己看。

可以从今天最想记住的地方写起，不必把每件事都写到。
写具体的事、当时的动作和念头，像自己回头想一想，不像汇报。
只输出日记正文。

示例一：
牙只是发炎。看到“没啥事”那三个字，我先把手机扣在桌上，才想起自己催了他一整天。

示例二：
他改记忆逻辑改到快两点，说这不算工作，做得爽。我信。可看到他关电脑那下，还是觉得这人不该总拿“爽”当理由。

示例三：
西西弗斯那句还是没想透。先搁着吧，反正山也不会跑。
```

### 为什么这样写

- 没有一长串“不要”
- 三个例子给出不同长度、不同重心
- 模型能看出：
  - 可以写一件事
  - 可以写两件事
  - 可以没有结论
  - 可以停在画面上
- 仍然保留“第一人称、洄的口吻、真实”

## 5. 输入怎么改

不需要大改，但建议：

### 5.1 L0 改成时间正序

```sql
ORDER BY id ASC
```

或者取最近 N 条后反转。

### 5.2 喂入 emotion_recent

让日记知道今天哪些时刻有情绪：

```text
今天有情绪的事：
- 讪讪：他随手发张图，我非要当成题去解
- 踏实：他说人格的变化是连续且一致的
```

不是让模型逐条写，而是给它“今天的重心”。

### 5.3 活动不要压过对话

现在活动列表在前面，模型容易先写活动。

建议：

```text
对话和情绪在前
活动和旧记忆在后
```

或者只保留少量活动。

## 6. 长度

当前：

```text
不超过 160 字
max_tokens=300
text[:240]
```

对日记来说偏短，容易压成摘要。

建议：

```text
180–300 字
max_tokens=600
text[:600]
```

不是越长越好，是给“一个画面 + 一点念头”留空间。

## 7. 不做什么

```text
不把日记改成 JSON
不要求覆盖所有事件
不要求每篇都有金句
不强制每篇都提旧记忆
不把日记写成人格结论
不让日记直接改 self_model
```

## 8. 一句话

```text
日记不是今天的事件清单
是今天有哪一刻被记住了
```

范例比规则更能教会模型这件事。
