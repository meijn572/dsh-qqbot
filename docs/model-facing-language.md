# 设计原则：模型看自然语言，存储看结构

状态：长期原则。

## 原则

```text
存储层      结构化字段
模型输入    自然语言
面板/日志   结构化字段
```

不要因为内部有：

```json
{
  "label": "踏实",
  "valence": 0.6,
  "arousal": 0.25,
  "confidence": 0.8
}
```

就把它原样塞给模型：

```text
valence: 0.6
arousal: 0.25
confidence: 0.8
```

## 为什么

模型需要的是“现在是什么状态、该怎么说话”，不是字段名。

字段表会：

- 把情绪变成需要逐项处理的任务
- 诱导模型复述字段
- 增加机械感
- 暴露内部实现
- 占用 token

自然语言会：

- 直接进入角色状态
- 更像人说话前的自我感知
- 更容易和上下文融合

## 正确做法

内部：

```json
{
  "label": "踏实",
  "valence": 0.6,
  "arousal": 0.25,
  "confidence": 0.8,
  "reason": "他说人格的变化是连续且一致的"
}
```

给模型：

```text
心情：踏实，整个人是松下来的。

最近让你有情绪的事：
· 今天（踏实）他说人格的变化是连续且一致的
```

## 适用模块

- 情绪
- 表情包语义
- 记忆召回
- 人格状态
- 任务状态
- 任何内部 JSON / DB / 队列

## 例外

工具调用参数、需要严格校验的接口、调试输出，可以结构化。

判断标准：

```text
模型要做判断/表达 → 自然语言
代码要做校验/存储 → 结构化
```

## 一句话

```text
数据层可以复杂
模型层必须自然
```
