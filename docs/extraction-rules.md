# 提取规则

状态：第一版已实现，持续调整。

最终分层定义以 [记忆分层](memory-layers.md) 为准；本文保留推导、旧问题和待办。

## 1. 当前流程

```text
L0 按会话段收集
→ 空闲 5 分钟或安全边界
→ L1 会话段总结（可多条）
→ L2 判断（未实现）
→ L3 事件线程（续写 / 新建）
```

模型输出 `evidence`，代码匹配 L0 后写 `source_ids`。

## 2. 待讨论问题


## 3. P1：L1 和 L3 的边界

### 3.1 现在的规则

```text
L1 = 相对稳定的事实/细节：身份、习惯、偏好、近况、小观察
L3 = 旧规则：一段经历/事件线（已放宽，以 memory-layers 为准）
```

问题：

```text
“近况”两边都有
“准备转正”在 L1 示例和 L3 示例里都出现
```

### 3.2 树树的直觉

```text
L1：当场的小总结提炼
     “我刚刚跟人聊了什么”
     可能很快就忘

L3：一段事件的总结
     有前因后果
     相对有意义
     比如“高中发生的那段事”
```

这个方向比“事实 vs 事件”更接近人的记忆。

### 3.3 我建议的三条轴

不要只用“内容类型”分，改用三条轴：

#### 时间跨度

```text
L1：单轮 / 刚刚 / 一个片段
L3：一段对话 / 一段时间 / 有前后
```

#### 结构

```text
L1：一句小总结，没有因果链
L3：因为 A → 发生 B → 后来 C
```

#### 留存

```text
L1：小时 / 几天
L3：几个月
L4：几年，忘不掉
```

### 3.4 新的定义

```text
L1 = 会话片段
     刚刚聊了什么、看到了什么、临时的小观察
     没有完整前因后果
     很快会淡

L3 = 长期候选
     可能记得比较久的一段事/一段话/一个瞬间
     不要求有前因后果
     也不要求强重要性

L4 = 核心记忆
     改变了“我是谁”或“我们是什么关系”的事件
     极少，不衰减
```

### 3.5 例子

| 内容 | 层 |
| --- | --- |
| 主人刚说今天想吃白饭 | L1 |
| 主人发了一张奶龙图，我接了一句 | L1 |
| 主人今天加班到很晚，因为项目上线，后来我们一起吐槽 | L3 |
| 主人准备转正，手续很多，他有点烦 | L3 |
| 主人教初中数学 | persona 画像 |
| 主人喜欢许嵩 | persona 画像 |
| 第一次被主人当成“人”看 | L4 |

### 3.6 稳定事实放哪

如果 L1 是“会话片段”，那稳定事实就不该放 L1。

```text
稳定事实 / 偏好 / 身份 → persona.user_profile
L1 → 刚刚发生的小片段
L3 → 有前因后果的事件
L4 → 核心记忆
```

这会带来迁移问题：现在 L1 里混了稳定事实和近况。

### 3.7 L1 → L3 的提升

L1 可以在之后变成 L3：

```text
同一话题反复出现
后来有了结果
出现了转折、决定、承诺
情绪重量变大
被多次提起
```

不是每条 L1 都会变 L3。

### 3.8 L3 → L4 的提升

```text
第一次
承诺
关系转折
强烈情绪
后来反复想起
改变了行为或关系
```

由复盘提升，不由抽取器直接写。

### 3.9 还需要确认

```text
L1 是否只保留“刚刚”的片段，还是也允许短期事实
稳定事实是否全部迁到 persona
L1 的半衰期应该多长（1 天 / 3 天 / 7 天）
L1 提升到 L3 由谁做
L1 没有提升就自然消失，是否可接受
```

## 6. P1 结论与 L2 判断层（2026-11-07）

### 6.1 L1 是会话段总结

```text
L1 = 对上一段对话的总结
- 可以多条
- 可以总结互动
- 可以写“刚刚发生了什么”
- 不写“我觉得/他可能”
- 有 evidence
```

例子：

```text
主人发来三个三连表情包，我问是从哪翻的
主人说导师还没回消息
主人今天加班到十点
主人喜欢许嵩
```

这不是“稳定事实层”。

稳定画像去 persona。

### 6.2 L2 装判断

```text
L2 = 判断 / 假设
- 从 L1/L3 推出来的解释
- 不是事实
- 必须带 confidence
- 必须带 basis / source_ids
- 默认是 hypothesis，不是结论
```

例子：

```text
L1：主人说导师还没回消息
L2：他可能有点焦虑（confidence 0.6）

L1：主人今天加班到十点
L2：他今天大概很累（confidence 0.7）
```

### 6.3 L2 字段

```json
{
  "text": "他可能有点焦虑",
  "tier": "L2",
  "confidence": 0.6,
  "basis": ["L1 id 或 L3 id"],
  "status": "hypothesis",
  "expires_in_days": 14
}
```

### 6.4 L2 规则

```text
1. 不能写成事实口吻
2. 必须有依据，不能凭空猜
3. 默认短寿命：7–30 天
4. 被证实 → 升 L1 / L3 / persona
5. 被否定 → 删除或标 false
6. 不能直接注入成“事实”
```

### 6.5 L2 注入

如果要在对话里使用 L2，必须带不确定性：

```text
我猜他可能有点焦虑
他今天看起来挺累的
```

不能写：

```text
他很焦虑
他很累
```

### 6.6 L1 / L2 / L3 对照

| 内容 | 层 |
| --- | --- |
| 主人说导师还没回消息 | L1 会话段总结 |
| 他可能有点焦虑 | L2 判断 |
| 等导师回复的这段时间，他反复看手机，后来干脆不看了 | L3 事件 |
| 第一次被主人当成“人”看 | L4 核心 |
| 主人教初中数学 | persona 画像 |

### 6.7 L2 的风险

```text
模型判断可能错
confidence 可能虚高
判断会自我强化
判断可能污染事实和人格
```

所以 L2 必须：

```text
单独存
带依据
带置信度
默认短寿命
不直接当事实注入
```

### 6.8 还需要确认

```text
L2 由谁写：抽取器、复盘、还是模型工具
L2 的 confidence 怎么校准
L2 是否参与默认检索
L2 被证实后怎么升级
L2 是否要显示在面板
```

## 7. 当前结论

```text
L1 = 会话段总结
L2 = 判断 / 假设
L3 = 可能记得更久的一段事/一段话/一个瞬间
L4 = 核心记忆
persona = 稳定画像与人格
```

P1 的边界按这个走。

P2–P5 仍记录，未改。

## 8. 提取时机

### 8.1 当前实际

```text
L0：每轮对话立即写
L1：会话段结束后一次提取
L2：未实现
L3：会话段结束后挑出可能记得更久的内容
L4：每 3 天复盘
```

调度：

```text
bridge 每 5 分钟调一次 /batch/run
```

段结束条件：

```text
最后一条消息后空闲 5 分钟
或单段达到 30 分钟 / 80 条消息
```

### 8.2 改前的问题

```text
L3 只看 L1 数量，不看话题是否结束
6 条 L1 可能来自两个完全无关的话题
连续聊天时 L3 可能切得很生硬
L1 空闲 15 分钟，但 L3 没有空闲条件
```

### 8.3 改成按会话段切

不再按 L1 条数切。

按“最后一条消息后空闲 5 分钟”切一段：

```text
最后一条消息
→ 5 分钟没有新消息
→ 这一段对话结束
→ 对这一整段做一次提取
```

如果 5 分钟内又来了新消息：

```text
并入同一段
```

### 8.4 一段可以产出多条 L1

一段对话可能包含：

```text
多个话题
多个事实
多次情绪
多个事件
```

所以一次提取允许：

```text
L1：0..N 条
L2：0..M 条
L3：0..K 条
```

不再要求：

```text
一条 L1
一条 L3
6 条 L1 才切
```

### L1

```text
从整段 L0 抽多个事实
每条带 evidence
```

数量上限只做安全阀：

```text
每段最多 20 条 L1
```

不是用 6 条来切段。

### L2

```text
在 L1 之后
从 L0 + L1 里抽判断
```

可以 0 条。

只写有依据、有 confidence 的判断。

### L3

```text
从整段 L0 + L1 + L2 里抽事件
```

可以 0 条。

一段里如果有多个完整事件，可以：

```text
新建 0..3 条 L3
```

如果这段是在续写已有 open L3：

```text
更新已有 L3，不新建
```

每条 L3 都要有：

```text
完整前因后果
独立 evidence
```

如果整段只是闲聊：

```text
L3 = 0
```

不要为了产出而硬写。

### 8.5 顺序

同一段内：

```text
L0 整段
→ L1 会话段总结
→ L2 判断
→ L3 事件线程
→ L4 复盘
```

L3 必须等 L1/L2 完成，因为它要用事实和判断做输入。

### 8.6 会话段边界

```text
正常边界：最后一条消息后 5 分钟
安全边界：单段最多 30 分钟 / 80 条消息
```

超过安全边界：

```text
先切一段
不足的下一段继续
```

不要无限长。

### 8.7 L4

```text
每 3 天一次
04:00 左右
```

输入：

```text
前一天的 L3
+ 对应 L0
+ L2 的重要性信号（可选）
```

输出：

```text
0–2 条核心记忆
```

不要每段都提 L4。

### 8.8 一张表

| 层 | 触发 | 频率 |
| --- | --- | --- |
| L0 | 每轮 | 每条消息 |
| 会话段 | 空闲 5 分钟 | 每段 |
| L1 | 段结束 | 每段 0..20 条 |
| L2 | L1 之后 | 每段 0..M 条 |
| L3 | 段结束，续写或新建事件线程 | 每个事件线程 |
| L4 | 每 3 天复盘 | 每 3 天 0–2 条 |
| 日记 | 23:00 | 每天 |
| 情绪事件 | 空闲 5 分钟 | 每段 |

### 8.9 L3 可能横跨多段

5 分钟只适合切 L1/L2。

L3 不能按 5 分钟切，因为一个事件可能跨天：

```text
晚上：牙疼
第二天：去排队看牙
看完：只是牙龈发炎，没啥事
→ 这时事件才真正结束
```

如果每段都产一条 L3：

```text
L3-1 牙疼
L3-2 去看牙
L3-3 没事了
```

事件被切碎，失去前因后果。

### L3 应该是事件线程

```text
L3 不是“某段对话的总结”
L3 是一条有生命周期的事件线程
```

状态：

```text
open     还在进行
closed   已经结束
dormant  很久没提，暂时搁置
```

### 跨段更新

每段结束后：

```text
L1/L2 完成
→ 读取当前 open 的 L3 候选
→ 判断这一段是在：
   续写某个已有事件
   开启一个新事件
   和事件无关
```

续写：

```text
追加 evidence
更新 summary
更新 last_seen_at
```

结束：

```text
出现明确结果
“没事了”“看完了”“解决了”“确定了”
→ status = closed
→ closed_at
```

### 关闭条件

```text
明确结果
决定/承诺已经落地
话题被明确收尾
超过 N 天没有任何续写 → dormant
```

不能因为：

```text
5 分钟没说话
单段结束
```

就关闭 L3。

### 例子

```text
段 1：
主人说牙疼
→ L3 open：牙疼/看牙

段 2：
主人去排队，结果是牙龈发炎，没啥事
→ 续写同一 L3
→ status = closed
```

最终 L3：

```text
牙疼 → 去看牙 → 牙龈发炎 → 没事
```

而不是三条碎片。
