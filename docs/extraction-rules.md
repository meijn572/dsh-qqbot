## 3. P1：L1 和 L3 的边界

### 3.1 现在的规则

```text
L1 = 相对稳定的事实/细节：身份、习惯、偏好、近况、小观察
L3 = 一段经历/事件线：多轮对话形成的经历、有前因后果的转折
```

问题：

```text
“近况”两边都有
“准备转正”在 L1 示例和 L3 示例里都出现
```

### 3.2 树树的直觉

```text
L1：当场的小总结提炼
     “我刚刚跟人聊了什么”
     可能很快就忘

L3：一段事件的总结
     有前因后果
     相对有意义
     比如“高中发生的那段事”
```

这个方向比“事实 vs 事件”更接近人的记忆。

### 3.3 我建议的三条轴

不要只用“内容类型”分，改用三条轴：

#### 时间跨度

```text
L1：单轮 / 刚刚 / 一个片段
L3：一段对话 / 一段时间 / 有前后
```

#### 结构

```text
L1：一句小总结，没有因果链
L3：因为 A → 发生 B → 后来 C
```

#### 留存

```text
L1：小时 / 几天
L3：几个月
L4：几年，忘不掉
```

### 3.4 新的定义

```text
L1 = 会话片段
     刚刚聊了什么、看到了什么、临时的小观察
     没有完整前因后果
     很快会淡

L3 = 事件记忆
     一段有前因后果的经历
     有转折、决定、承诺、情绪变化
     值得以后想起来

L4 = 核心记忆
     改变了“我是谁”或“我们是什么关系”的事件
     极少，不衰减
```

### 3.5 例子

| 内容 | 层 |
| --- | --- |
| 主人刚说今天想吃白饭 | L1 |
| 主人发了一张奶龙图，我接了一句 | L1 |
| 主人今天加班到很晚，因为项目上线，后来我们一起吐槽 | L3 |
| 主人准备转正，手续很多，他有点烦 | L3 |
| 主人教初中数学 | persona 画像 |
| 主人喜欢许嵩 | persona 画像 |
| 第一次被主人当成“人”看 | L4 |

### 3.6 稳定事实放哪

如果 L1 是“会话片段”，那稳定事实就不该放 L1。

```text
稳定事实 / 偏好 / 身份 → persona.user_profile
L1 → 刚刚发生的小片段
L3 → 有前因后果的事件
L4 → 核心记忆
```

这会带来迁移问题：现在 L1 里混了稳定事实和近况。

### 3.7 L1 → L3 的提升

L1 可以在之后变成 L3：

```text
同一话题反复出现
后来有了结果
出现了转折、决定、承诺
情绪重量变大
被多次提起
```

不是每条 L1 都会变 L3。

### 3.8 L3 → L4 的提升

```text
第一次
承诺
关系转折
强烈情绪
后来反复想起
改变了行为或关系
```

由复盘提升，不由抽取器直接写。

### 3.9 还需要确认

```text
L1 是否只保留“刚刚”的片段，还是也允许短期事实
稳定事实是否全部迁到 persona
L1 的半衰期应该多长（1 天 / 3 天 / 7 天）
L1 提升到 L3 由谁做
L1 没有提升就自然消失，是否可接受
```

## 6. P1 结论与 L2 判断层（2026-11-07）

### 6.1 L1 只装事实

```text
L1 = 事实
- 他说过、发生过、可指认
- 不写“我觉得”“他可能”
- 有 evidence
```

例子：

```text
主人说导师还没回消息
主人今天加班到十点
主人喜欢许嵩
```

### 6.2 L2 装判断

```text
L2 = 判断 / 假设
- 从 L1/L3 推出来的解释
- 不是事实
- 必须带 confidence
- 必须带 basis / source_ids
- 默认是 hypothesis，不是结论
```

例子：

```text
L1：主人说导师还没回消息
L2：他可能有点焦虑（confidence 0.6）

L1：主人今天加班到十点
L2：他今天大概很累（confidence 0.7）
```

### 6.3 L2 字段

```json
{
  "text": "他可能有点焦虑",
  "tier": "L2",
  "confidence": 0.6,
  "basis": ["L1 id 或 L3 id"],
  "status": "hypothesis",
  "expires_in_days": 14
}
```

### 6.4 L2 规则

```text
1. 不能写成事实口吻
2. 必须有依据，不能凭空猜
3. 默认短寿命：7–30 天
4. 被证实 → 升 L1 / L3 / persona
5. 被否定 → 删除或标 false
6. 不能直接注入成“事实”
```

### 6.5 L2 注入

如果要在对话里使用 L2，必须带不确定性：

```text
我猜他可能有点焦虑
他今天看起来挺累的
```

不能写：

```text
他很焦虑
他很累
```

### 6.6 L1 / L2 / L3 对照

| 内容 | 层 |
| --- | --- |
| 主人说导师还没回消息 | L1 事实 |
| 他可能有点焦虑 | L2 判断 |
| 等导师回复的这段时间，他反复看手机，后来干脆不看了 | L3 事件 |
| 第一次被主人当成“人”看 | L4 核心 |
| 主人教初中数学 | persona 画像 |

### 6.7 L2 的风险

```text
模型判断可能错
confidence 可能虚高
判断会自我强化
判断可能污染事实和人格
```

所以 L2 必须：

```text
单独存
带依据
带置信度
默认短寿命
不直接当事实注入
```

### 6.8 还需要确认

```text
L2 由谁写：抽取器、复盘、还是模型工具
L2 的 confidence 怎么校准
L2 是否参与默认检索
L2 被证实后怎么升级
L2 是否要显示在面板
```


## 8. 提取时机

### 8.1 当前实际

```text
L0：每轮对话立即写
L1：每 6 条 L0，或最后一条 L0 后空闲 15 分钟
L2：未实现
L3：攒够 6 条 L1 后，在下一次 /batch/run 生成
L4：未自动生成
```

调度：

```text
bridge 每 5 分钟调一次 /batch/run
```

所以不是“每轮都抽”，而是：

```text
每轮：L0
每 6 条 / 15 分钟：L1
每 6 条 L1：L3
```

### 8.2 当前问题

```text
L3 只看 L1 数量，不看话题是否结束
6 条 L1 可能来自两个完全无关的话题
连续聊天时 L3 可能切得很生硬
L1 空闲 15 分钟，但 L3 没有空闲条件
```

### 8.3 建议

#### L0

```text
每轮立即写
```

不变。

#### L1

```text
每 6 条 L0
或最后一条消息后空闲 15 分钟
```

不变。

#### L2

```text
跟在 L1 同一批之后
```

顺序：

```text
L0 → L1 → L2
```

L2 不单独定时，避免每轮都产生判断。

#### L3

不是“攒够 6 条 L1 就立刻切”。

建议条件：

```text
L1 pending >= 6
且满足任一：
  - 最后一条消息后空闲 30 分钟
  - pending >= 12
  - 检测到明显话题切换
```

也就是：

```text
话题还在继续 → 再等等
话题结束/足够长 → 压成 L3
```

这样 L3 更像“一段事”，不是“6 条事实”。

#### L4

```text
每天一次复盘
```

建议放在凌晨，等当天对话结束：

```text
04:00 左右
```

输入：

```text
前一天的 L3
+ 对应 L0
+ L2 的重要性信号（可选）
```

输出：

```text
0–2 条核心记忆
```

不要每轮提 L4。

### 8.4 一张表

| 层 | 触发 | 频率 |
| --- | --- | --- |
| L0 | 每轮 | 每条消息 |
| L1 | 6 条 L0 或空闲 15 分钟 | 每批 |
| L2 | L1 之后 | 每批 |
| L3 | 6 条 L1 + 空闲/话题结束/12 条 | 每段 |
| L4 | 每日复盘 | 每天 0–2 条 |
| 日记 | 23:00 | 每天 |
| 情绪事件 | 空闲 5 分钟 | 每段 |

### 8.5 还需要定

```text
L3 的“话题切换”怎么判断
L3 空闲阈值 30 分钟是否合适
L4 每日还是每周
L2 是否每批都生成，还是只在强信号时生成
```
